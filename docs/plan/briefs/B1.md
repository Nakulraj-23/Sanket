# B1 — Data, quality checks, cleaning (Sonnet)
Read also: `docs/handoffs/B0.md`. Own: `sanket/pipeline/`, `data/splits/`, `data/stress/`, `tests/data/`, `tests/unit/test_pii*.py`, `test_clean*.py`.
Build:
1. `load.py`: read the raw CSVs with pandas, rename `category` to `intent`, add `row_id`.
2. `pii.py: redact(text)`: emails, phone numbers (Indian `+91`/10-digit and international), card numbers (13 to 19
   digits with spaces or dashes, **only if the Luhn checksum passes**; write `luhn_ok` yourself), account numbers
   (9 to 18 digits near words like account/acct/a/c/IBAN). Placeholders per CONTRACTS. Must not redact amounts,
   dates, short codes. Return counts by kind.
3. `clean.py`: `validate` and `clean` per CONTRACTS. Normalise: Unicode NFKC, collapse whitespace, lower-case,
   keep Devanagari. `clean(clean(x).text)` must equal `clean(x)` (test it).
4. `quality.py: check_frame(df, name)`: nulls, empty text, unknown intent, duplicate normalised text, text length
   bounds, class count floor; `check_splits(...)`: no normalised text shared between any two splits. Raises with a
   clear message. Test: each check fails on a corrupted copy.
5. `split.py` (`make data`): splits exactly per CONTRACTS, run `clean` on every text, run the quality checks, write
   `data/splits/*.csv` and print counts per split and per team.
6. `perturb.py`: `add_typos(text, rate, seed)` (swap, drop, duplicate characters) and `hinglishify(text, seed)`
   (replace common English words and phrases with romanised Hindi from a dictionary of at least 80 entries, e.g.
   "my"→"mera", "not working"→"kaam nahi kar raha", "money"→"paisa"). Both deterministic. `hinglishify` output is
   synthetic and is used only for the drift scenario, never for training or reported accuracy.
7. `data/stress/hinglish.csv`: write 60 rows **by hand**, as an Indian bank customer would type: about 40 romanised
   Hinglish, 10 Devanagari Hindi, 10 mixed with English. Cover all 7 teams, at least 15 high-urgency, include typos
   and SMS-style spelling. Do not generate them with `hinglishify`. Column `note` = what makes the row hard.
8. `data/stress/pii_probe.csv`: 40 hand-written rows with fake PII (card `4111 1111 1111 1111` and other Luhn-valid
   test numbers, `name@example.com`, `98xxxxxxxx` phones) and 10 negatives that must stay unchanged (amounts, dates,
   order ids, a 16-digit number that fails Luhn). Test: `redact` matches `expected_redacted` on every row.
Tests: Luhn on known valid and invalid numbers; determinism of splits; no split overlap; row counts add up.
Done when: `make data` runs in under 30 seconds and `pytest tests/data tests/unit` is green.
Handoff: rows per split, rows removed as train/test duplicates, class counts (min, max), PII probe pass rate,
any intent whose team or urgency in the rubric looked wrong to you.
