# B3 — PyTorch challenger, ONNX, benchmark, drift maths (Sonnet)
Read also: handoffs B0, B1, Q1. Own: `sanket/models/nn/`, `sanket/bench.py`, `sanket/monitoring/`, `artifacts/nn/`,
`tests/unit/test_drift*.py`, `tests/model/test_nn*.py`. Run `make link-torch` first; never `pip install torch`.
Build:
1. `tokenizer.py`: lower-case word tokens from `clean` text; vocabulary from `train` only (min count 2), ids 0 = pad,
   1 = unknown; fixed length 48; saved as `vocab.json`. Plain Python, no torch.
2. `net.py: IntentNet`: `Embedding(V, 64, padding_idx=0)` → mean over non-pad tokens → dropout → `Linear(64, 128)` →
   ReLU → `Linear(128, 77)`. `forward` under 15 lines with a comment per line.
3. `train.py` (`make train-nn`): Adam, cross-entropy, batch 64, early stopping on `val` macro-F1, seed 42, CPU,
   under 5 minutes. At most 3 variants in total (for example: plus hashed character-trigram ids; larger embedding).
   Log every variant and its `val` score in `docs/EXPERIMENTS.md`. Pick by `val`, then evaluate once on `test`.
4. `export_onnx.py`: export with dynamic batch size to `artifacts/nn/model.onnx` (under 10 MB). Parity test: max
   absolute difference between torch and onnxruntime probabilities under 1e-4 on 200 texts (skipped without torch).
   Commit `artifacts/nn/expected.json` (probabilities for 20 fixed texts) so CI can test `OnnxModel` without torch.
5. `onnx_model.py: OnnxModel` per CONTRACTS, onnxruntime only, one intra-op thread.
6. `bench.py` (`make bench`): for baseline, NN in torch (if importable) and NN in ONNX: `test` intent accuracy and
   macro-F1, team accuracy, single-ticket latency p50 and p95 over 1,000 calls after 50 warm-up calls including
   text preparation, throughput at batch 64, file size. Write `docs/bench.md` and `artifacts/nn/card.json`.
   If the baseline artifact is missing, say so in the handoff; the orchestrator will run `make bench` later.
   **Report the result as measured.** If the NN loses, write one paragraph with the likely reason and the
   evidence; do not keep tuning. The linear model serves in both cases (design decision, not yours to change).
7. `monitoring/drift.py` per CONTRACTS, NumPy only. `psi`: shared bin edges from the reference, a floor of 1e-4
   on empty bins. `ks_2samp`: sort both samples, walk the merged values to get the largest gap between the two
   empirical CDFs; p-value from the asymptotic Kolmogorov series. `drift_report` applies the CONTRACTS status rules
   to n_tokens (KS), oov_rate (KS), team_conf (KS), predicted-team mix (PSI). Each function under 25 lines, commented
   so a student can follow the formula. Until B2's `reference.json` exists, test with synthetic references.
Tests: `ks_2samp` equals `scipy.stats.ks_2samp` (statistic to 1e-9, p-value to 1e-3) on 5 seeded cases incl. ties
and unequal sizes; PSI is 0 for identical samples, grows with shift, matches a hand-computed 3-bin example;
insufficient data below 200; shifted synthetic sample turns red.
Done when: `make train-nn bench` and the tests pass. Handoff: bench table, variants tried, parity, file sizes.
