# B5 — Dashboard: the pipeline view (Sonnet)
Read also: `docs/handoffs/B0.md` and `fixtures/*.json` (the frozen response shapes). Own: `web/`.
You build against fixtures; the API arrives one wave later. Do not read Python source.
Build (React 18 + Vite 5, plain JavaScript, no router, no state library, no chart library, CSS in one file):
1. `src/api.js`: every call in the CONTRACTS REST table. Base URL from `VITE_API_URL`. On page load call `/health`
   with a 4-second timeout: success → mode **live**; failure → mode **replay**, load `/replay.json`, retry `/health`
   every 15 seconds and switch to live when it answers. In replay mode: samples come from `replay.samples`, reviews
   are applied in memory and labelled "replay, not saved", free text is disabled with a one-line reason.
   Until B4 delivers the real file, generate `public/replay.json` from the fixtures with `scripts/fixtures_to_replay.mjs`.
2. Header: SANKET, "संकेत — signal", Live/Replay badge, model version.
3. Try-it row: textarea (2,000 char counter), Submit, six sample chips (clear, urgent fraud, ambiguous, fake PII,
   Hinglish, gibberish). 422 errors shown inline.
4. Pipeline strip: seven cards (Ingest, Clean, Classify, Explain, Route, Review, Monitor) with arrows and a return
   arrow "retrain gate". After a result, cards light up left to right showing `trace[i].summary` and `ms`. Review
   shows the ticket's status; Monitor shows the drift status.
5. Drawer on card click, four tabs: What it does, Why this way, Code (`stages[i].file`, `function`, `code` in a
   `<pre>`), Live example (render `trace[i].detail` per stage: Clean = before/after with placeholders highlighted;
   Classify = top-5 bars + second opinion from `/compare`; Explain = words with weights, bar per term; Route = team
   bars, p_high, thresholds, rule in words; Review = form; Monitor = indicator table).
6. Panels: Review queue (list, confirm, override with top-5 intents + searchable select grouped by team, optional
   urgency, note; handle 409 with a message), Monitor (four indicators with chips, override rate by team, buttons
   "Simulate Hinglish surge" and "Reset" that call `/demo/scenario` then `/monitor/drift/run`), Model (champion
   metrics, LR-versus-NN table, registry history with reasons).
7. Render all text from the API as text, never as HTML. Keyboard: cards and chips are buttons; drawer closes on Esc.
   Layout works at 1280 px and at 390 px (strip scrolls sideways). Light theme, one accent colour.
8. `e2e/` with Playwright 1.47.2 (see CONTRACTS for the browser path): replay mode (no API): chip → seven cards
   fill → drawer tabs show content → override a queued ticket → badge reads Replay. Live-mode spec written now,
   tagged `@live`, run when the orchestrator tells you the API is up.
9. `vercel.json` (SPA, build `npm run build`, output `dist`). `make web` = dev server; `npm test` = e2e.
Done when: `npm run build` and the replay e2e pass; bundle under 300 kB gzipped; `node_modules` under 150 MB.
Handoff: how to run both modes, bundle size, any fixture field you needed but did not have.
