# B4 — API, review queue, seed, replay (Sonnet)
Read also: handoffs B0, B1, B2, B3, Q2; `docs/plan/EXPLAINABILITY.md` (text for the stage cards).
Own: `sanket/{service,review,stages}.py`, `sanket/sql/`, `sanket/api/`, `scripts/`, `tests/api/`.
Build:
1. `service.py: process_ticket(text, channel) -> TicketResult`: validate → clean → classify → explain → route →
   store ticket and prediction in one transaction → return the trace. Time each stage with `time.perf_counter`.
   Models and thresholds load once at start-up from the champion in `registry.json`. Never store or log raw text;
   `detail.before_masked` shows the input with PII characters replaced by `•`, built in memory only.
2. `review.py: save_review(...)`: the single-transaction rule in CONTRACTS (conditional update + unique
   constraint → 409). `queue()` orders urgent first, then oldest.
3. `stages.py`: for the seven stages: `id, title, what, why` (from EXPLAINABILITY.md, three sentences each, no
   undefined jargon), `file`, `function`, and `code` = `inspect.getsource` of the real function (redact, clean,
   predict_proba, explain, decide, save_review, psi). Test: every `file` exists and `code` is non-empty.
4. `sql/metrics.sql`: three named hand-written queries (override rate by team with JOIN + GROUP BY; auto-routed
   share per day; average latency per model version), executed with `text()`. Comment each query in plain words.
5. `api/app.py` + routers: every endpoint in CONTRACTS with the exact shapes in `fixtures/`. CORS from settings.
   Request body limit, 2,000-char limit, ticket cap (delete oldest non-seed rows beyond 5,000). `/compare` stores nothing.
   `/demo/scenario`: `hinglish_surge` runs up to 300 `stream` rows through `hinglishify` and the pipeline with
   channel `scenario`; `reset` deletes scenario tickets. `/monitor/drift/run` uses `drift_report` on the latest 500.
6. `scripts/seed.py` (`make seed`, under 60 seconds, idempotent): fresh DB; push 400 `stream` rows through the
   pipeline (append a templated fake-PII sentence to 10%); a simulated reviewer (`sim-reviewer`, uses the true
   labels held in memory, never written to the DB except through `final_intent`) reviews all but 15 queued
   tickets; run one drift report. `make serve` = uvicorn on port 8000 with reload.
7. `scripts/make_replay.py` (`make replay`): call the app through `TestClient` for the six sample chips plus six
   more tickets, queue, drift before and after `hinglish_surge`, metrics, model, stages, taxonomy, compare; write
   `web/public/replay.json` in the CONTRACTS shape. Test: it validates against the schemas and its
   `model_version` equals the champion.
8. `scripts/space_bundle.py` (`make space-bundle`): write `dist/space/` (Dockerfile, Space `README.md` with front
   matter `sdk: docker`, `app_port: 7860`, and the files the image needs). `docs/DEPLOY.md`: the candidate's steps
   for Hugging Face Spaces and Vercel, plus Render as the alternative; say which steps need their accounts.
Tests (`tests/api/`, httpx `TestClient`, temp DB): every endpoint against its fixture shape; 201/404/409/422;
PII probe text posted then absent from every DB column; review race with two threads gives one 200 and one 409;
`sys.modules` has no `torch` after a request; 20 parallel POSTs succeed.
Done when: `make seed serve` works and `pytest tests/api` passes. Handoff: endpoint list, p50/p95 of POST
`/tickets` over 200 calls, seed counts (auto, queued, reviewed, overrides), cold-start time, anything missing in fixtures.
