# Q1 — Data audit (Opus)
Read: handoffs B0, B1; then `sanket/pipeline/`, `sanket/taxonomy.yaml`, `data/`.
You are a sceptical reviewer. The last project's first dataset was too easy and a reviewer caught it. Do not
rewrite code. Report in `docs/handoffs/Q1.md`, ranked HIGH/MED/LOW, each with evidence (a number) and a suggested fix.
Check, and write a small script per check under `tests/data/` where it can be a test:
1. Leakage across splits: exact, normalised and near-duplicate texts (token-set Jaccard >= 0.9) between train, val,
   stream and test. Report counts. Test rows must be untouched and complete (3,080).
2. Too easy: on train→val, measure majority class, a depth-3 tree on TF-IDF, a one-keyword-per-intent rule, a
   length-only model, and a quick TF-IDF + LR. Expected: trivial baselines far below LR, LR intent macro-F1 in
   0.85 to 0.93. Outside the band, or any trivial baseline above 0.5, is a HIGH finding: name the cause.
3. Label-pure tokens: tokens with support >= 30 that occur in one intent only. Decide for each whether it is a
   legitimate word ("atm") or an artefact (an id, a template marker).
4. Label noise: sample 150 train rows, judge the intent yourself, report the disagreement rate and examples.
   This becomes a stated limitation, not a fix.
5. Rubric: read all 77 intent→team and intent→urgency assignments against 5 example texts each. List the debatable
   ones with a recommendation. Check class balance per team and per urgency in every split.
6. PII: attack `redact` with at least 30 formats not in the probe (spaced and dashed cards, `+91-` phones, emails
   with dots and plus signs, numbers inside words, Devanagari digits). Report misses and false redactions.
7. Quality checks: corrupt copies of the splits in 10 ways; report which corruptions pass unnoticed.
8. Hinglish set: 60 rows, all teams, >= 15 high-urgency, labels plausible, reads like a person wrote it, no row
   copied from the dataset. `clean` is idempotent and keeps Devanagari.
9. Determinism: `make data` twice gives byte-identical splits.
Add tests for what you verified. Finish with a short list "verified OK". Re-check only your own items after the fix round.
